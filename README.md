# Nano Banana 2 — Gemini app vs Interactions API

Compares multi-turn image editing with Nano Banana 2 in the **Gemini app** against the same
edit chains run through the **Gemini API** (multi-turn editing with the Interactions API,
`gemini-3.1-flash-image`, 2K output, high thinking level).

Two experiments, each a chain of 10 edits applied to the same starting image:

- **Exp 1** — living-room scene, 10 heterogeneous edits (color change, object add/remove,
  material change, spatial move, background, lighting, …)
- **Exp 2** — fruit still life, 10 additive edits (one fruit per turn)

## Layout

- `data/exp1/`, `data/exp2/` — outputs saved from the Gemini app
  (`0.jpeg` = starting image, `N.jpeg` = result after edit N)
- `data/exp1_api/`, `data/exp2_api/` — outputs of the API chains, same numbering
  (generated by the notebooks)
- `notebooks/exp1.ipynb`, `notebooks/exp2.ipynb` — run the API edit chain and render an
  interactive comparison: a slider to pick the turn plus a wipe slider on the image
  (left: Gemini app, right: API)

The comparison widget needs a live notebook frontend (VS Code / Jupyter); GitHub's static
notebook preview won't run it.

## Setup

```sh
uv sync
cp .env.example .env  # then add your Gemini API key
```

Run the notebooks with the project virtualenv (`.venv`) as kernel. Re-running a notebook
re-executes the whole chain against the API and overwrites `data/exp*_api/`.
